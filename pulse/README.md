# Пульс

Финансовое PWA для телефона и компьютера. На iPhone можно установить на экран «Домой» из Safari. Это веб-приложение с отдельным окном и офлайн-режимом, а не нативная iOS-сборка.

## Разделы

- **Обзор:** планируемый бюджет, остаток, все неоплаченные траты выбранного месяца и отдельная карточка обязательных платежей. Редактирование бюджета раскрывается по нажатию; категории остаются на главном экране.
- **Обязательные платежи:** регулярные платежи с названием, суммой и днем месяца. Список сортируется по дню, сверху показывается общая сумма на месяц.
- **Кредиты:** название, остаток задолженности, ежемесячный платеж, дата ближайшего платежа и необязательная дата окончания. Верхняя карточка показывает общую задолженность и сумму ежемесячных платежей по всем кредитам.
- **Аналитика:** структура расходов и распределение по неделям.
- **Настройки:** аккаунт, облачная синхронизация, экспорт и импорт JSON.

Вкладка «Планы» удалена из нижней навигации. История всех трат, включая оплаченные, открывается из обзора кнопкой «Все траты».

Обязательные платежи и кредиты хранятся отдельно от расходных записей. Их суммы показываются для контроля, но автоматически не уменьшают планируемый бюджет: если пользователь уже внес такой платеж как трату, повторного вычитания не происходит.

## Архитектура

- `index.html`, `styles.css`: готовая оболочка и адаптивный интерфейс. Бюджет и категории находятся на главном экране; редактор бюджета раскрывается по нажатию. Нижняя навигация содержит обзор, обязательные платежи, кредиты, аналитику и настройки.
- `app.js`: состояние, формы, навигация с сохранением позиции прокрутки, сохранение и синхронизация.
- `loans.js`: отдельные чистые правила валидации и календаря кредитов.
- Локальные данные сохраняются в прежнем `pulse-finance-v1`; старые копии без `loans` или `mandatoryPayments` читаются с пустыми списками. Экспорт, импорт и облачный JSON включают кредиты и обязательные платежи.
- `sw.js`: кеш оболочки, ограниченный папкой приложения. Код и библиотека авторизации доступны офлайн; облачные запросы не кешируются. Ссылки подтверждения не сохраняются как отдельные страницы кеша. Обновление активируется после закрытия старых вкладок, чтобы не прерывать ввод в формах.
- `vendor/supabase-2.45.4.js`: прежняя фиксированная версия Supabase JS, поставляемая вместе с приложением вместо внешнего CDN. Источник: официальный npm-пакет `@supabase/supabase-js@2.45.4`, `dist/umd/supabase.js`; лицензия рядом.

Сервер: существующий Supabase Auth + Postgres (`pulse_finance_state`) + Realtime. В клиенте используется только публичный publishable key. RLS ограничивает строки условием `auth.uid() = user_id`; кредиты и обязательные платежи помещаются в существующий JSON, миграция таблицы не нужна.

Ограничения существующей синхронизации: один снимок состояния на аккаунт, сравнение по времени изменения; одновременные изменения разных устройств не объединяются по отдельным записям. Локальный профиль пока один на браузер. Для полноценного многопользовательского режима следующий отдельный этап: локальное хранилище по аккаунтам и разрешение конфликтов отдельных записей. После обновления нужно перезапустить приложение на всех устройствах: старый клиент не знает новые поля и может перезаписать облачное состояние без них.

## Регистрация

Клиент проверяет email и пароль, блокирует повторное нажатие во время запроса, сохраняет канонический адрес возврата без параметров сборки, показывает коды ошибок доставки и позволяет повторить подключение. Ссылка с ошибкой подтверждения открывает настройки с объяснением.

Проверено 21.09.2026 на действующем проекте: signup включён, email-провайдер включён, подтверждение email обязательно, социальные провайдеры выключены. RLS-политики чтения/записи проверены. Почтовая конфигурация требует отдельного доступа в панель Supabase; доставка реального письма не подтверждена. **Это обновление клиентского кода не подтверждает исправление серверной отправки писем.**

Для завершения проверки владельцу проекта нужно предоставить вход в панель Supabase; там проверяются SMTP, URL Configuration и ошибки Auth. Встроенный отправитель Supabase ограничивает адресатов членами команды проекта. Для произвольных адресатов нужен настроенный SMTP. Подтверждение email не отключается.

Официальные источники:
- https://supabase.com/docs/guides/auth/auth-smtp
- https://supabase.com/docs/guides/auth/passwords
- https://supabase.com/docs/guides/auth/rate-limits

## Запуск и проверка

```sh
cd pulse
npm ci
npm test
npm run check
npm start
```

Открыть `http://localhost:8765/`. Для публикации сборка не требуется: файлы отдаются статически. `jsdom` используется только для тестов, не загружается пользователю.

Тесты проверяют CRUD кредитов и обязательных платежей через DOM-события, сортировку платежей, отдельный расчет бюджета, перезапуск, старые копии, безопасный вывод названий, сохранность обычных трат, обработку Auth-ошибок, синхронизацию и кеширование. DOM-тесты не заменяют проверку Safari, реальную доставку письма и синхронизацию двух авторизованных устройств.
