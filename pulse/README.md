# Пульс

Финансовое PWA для телефона и компьютера. На iPhone можно установить на экран «Домой» из Safari. Это веб-приложение с отдельным окном и офлайн-режимом, а не нативная iOS-сборка.

## Разделы

- **Обзор:** остаток после неоплаченных трат в плане, планируемый бюджет, разделение оплаченного и предстоящего. На главной видны три ближайшие неоплаченные траты; остальные доступны во вкладке «Траты». Бюджет редактируется кнопкой с карандашом.
- **Траты:** фильтры «Предстоит», «Оплачено» и «Все», сумма выбранного списка, редактирование и отметка оплаты. Формы открываются снизу на телефоне. Отметку оплаты и удаление можно отменить из уведомления.
- **Регулярные платежи:** повторяющиеся расходы с названием, суммой и днем месяца. Открываются из обзора или трат. Кнопка «Добавить в план» создает одну трату на платеж в выбранном месяце; повторное нажатие не создает дубль.
- **Кредиты:** остаток долга и ежемесячный платеж. Неуказанный долг отображается как «Не указан», введенный ноль сохраняется как ноль. Кредиты сортируются по дню платежа; 31-е число переносится на последний день короткого месяца без изменения дня следующих платежей.
- **Анализ:** расходы по категориям и неделям, фильтр всех трат в плане или только оплаченных. Нулевые значения не рисуются как ненулевые столбики.
- **Настройки:** открываются через аватар. Содержат аккаунт, облачную синхронизацию, категории, экспорт и импорт JSON.

Нижняя навигация содержит «Обзор» и «Анализ», между ними находится кнопка добавления. Все траты доступны из обзора, кредиты из настроек. Действие кнопки добавления зависит от открытого раздела.

Остаток по плану равен введенному бюджету выбранного месяца минус сумму неоплаченных трат этого месяца. Оплаченные траты остаются в аналитике, но не уменьшают остаток. После отметки оплаты плановый остаток увеличивается на сумму такой траты. Обязательные платежи и кредиты хранятся отдельно и автоматически не уменьшают бюджет.

## Архитектура

- `index.html`, `styles.css`: интерфейс по согласованному макету, единые цвета, размеры, карточки, иконки и формы. Версия 1.4.1 уменьшает заголовки, карточки и высоту форм, ограничивает ширину поля даты и учитывает видимую область при открытии клавиатуры. Форма траты открывается без автоматической клавиатуры. На компьютере сохраняется ширина мобильного приложения; демонстрационные данные макета не добавляются.
- `app.js`: состояние, формы, навигация с сохранением позиции прокрутки, сохранение и синхронизация.
- `loans.js`: отдельные чистые правила валидации и календаря кредитов.
- Локальные данные сохраняются в прежнем `pulse-finance-v1`; старые копии без `loans` или `mandatoryPayments` читаются с пустыми списками. Экспорт, импорт и облачный JSON включают кредиты и обязательные платежи. Необязательные поля `expense.mandatoryPaymentId`, `loan.paymentDay` и nullable `loan.balance` сохраняются при перезапуске и синхронизации.
- `sw.js`: кеш оболочки, ограниченный папкой приложения. Код и библиотека авторизации доступны офлайн; облачные запросы не кешируются. Ссылки подтверждения не сохраняются как отдельные страницы кеша. Обновление активируется после закрытия старых вкладок, чтобы не прерывать ввод в формах.
- `vendor/supabase-2.45.4.js`: прежняя фиксированная версия Supabase JS, поставляемая вместе с приложением вместо внешнего CDN. Источник: официальный npm-пакет `@supabase/supabase-js@2.45.4`, `dist/umd/supabase.js`; лицензия рядом.

Сервер: существующий Supabase Auth + Postgres (`pulse_finance_state`) + Realtime. В клиенте используется только публичный publishable key. RLS ограничивает строки условием `auth.uid() = user_id`; кредиты и обязательные платежи помещаются в существующий JSON, миграция таблицы не нужна.

Ограничения существующей синхронизации: один снимок состояния на аккаунт, сравнение по времени изменения; одновременные изменения разных устройств не объединяются по отдельным записям. Локальный профиль пока один на браузер. Для полноценного многопользовательского режима следующий отдельный этап: локальное хранилище по аккаунтам и разрешение конфликтов отдельных записей. После обновления нужно перезапустить приложение на всех устройствах: старый клиент не знает новые поля и может перезаписать облачное состояние без них.

## Регистрация

Клиент проверяет email и пароль, блокирует повторное нажатие во время запроса, сохраняет канонический адрес возврата без параметров сборки, показывает коды ошибок доставки и позволяет повторить подключение. Ссылка с ошибкой подтверждения открывает настройки с объяснением.

Проверено 21.09.2026 на действующем проекте: signup включён, email-провайдер включён, подтверждение email обязательно, социальные провайдеры выключены. RLS-политики чтения/записи проверены. Почтовая конфигурация требует отдельного доступа в панель Supabase; доставка реального письма не подтверждена. **Это обновление клиентского кода не подтверждает исправление серверной отправки писем.**

Для завершения проверки владельцу проекта нужно предоставить вход в панель Supabase; там проверяются SMTP, URL Configuration и ошибки Auth. Встроенный отправитель Supabase ограничивает адресатов членами команды проекта. Для произвольных адресатов нужен настроенный SMTP. Подтверждение email не отключается.

Официальные источники:
- https://supabase.com/docs/guides/auth/auth-smtp
- https://supabase.com/docs/guides/auth/passwords
- https://supabase.com/docs/guides/auth/rate-limits

## Запуск и проверка

```sh
cd pulse
npm ci
npm test
npm run check
npm start
```

Открыть `http://localhost:8765/`. Для публикации сборка не требуется: файлы отдаются статически. `jsdom` используется только для тестов, не загружается пользователю.

40 тестов проверяют поведение форм при изменении видимой области экрана, фильтры трат, отмену оплаты и удаления, защиту регулярных платежей от дублей, неуказанный долг, сохранность скрытой категории при редактировании, CRUD кредитов и обязательных платежей через DOM-события, сортировку платежей, отдельный расчет бюджета, перезапуск, старые копии, безопасный вывод названий, сохранность обычных трат, обработку Auth-ошибок, синхронизацию и кеширование. Дополнительно интерфейс проверен в Chromium на ширинах 320, 360, 390, 430, 768 и 1280 px, включая формы, редактирование, перезапуск и отсутствие горизонтального переполнения. Эти проверки не заменяют проверку Safari, реальную доставку письма и синхронизацию двух авторизованных устройств.

## Версия 1.5.0

Светлая тема с коралловым акцентом: отдельные карточки остатка и бюджета, недельные ярлыки дат и нижняя панель «Обзор / добавить / Анализ». Общая сумма трат, полоса бюджета и ее легенда убраны с главной. Все траты открываются по ссылке «Все», существующие кредиты доступны в настройках. Записи, ключ локального хранилища и облачный формат сохранены.

В разделе «Регулярные» появилась кнопка «Собрать месяц». Выберите месяц, отметьте платежи и при необходимости раскройте «Сумма и дата» для изменения отдельной записи. Эти изменения не меняют шаблон. Дни 29–31 переносятся на последний день короткого месяца. Уже добавленные шаблоны отключены; перед сохранением проверка повторяется, включая оплаченные записи. Все выбранные записи сохраняются одним действием; при ошибке локального сохранения пакет отменяется, форма остается открытой.

Недельные даты на главной фильтруют только список предстоящих платежей. Повторное нажатие снимает фильтр. Общий остаток всегда рассчитывается по полному месяцу.
